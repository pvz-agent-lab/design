# CLI、SDK 共享控制后端

共享后端是在线会话与执行资源的权威拥有者。它集成宿主/IPC、分支 checkout、checkpoint、脚本任务和记录服务，供 CLI、SDK 及其上层调用者共同使用。它不决定游戏策略或搜索方向。

## 内部模块与展开文档

后端包含会话/worker 注册、控制权仲裁、分支引用、checkout 规划与执行、checkpoint 缓存、脚本服务、任务/请求日志，以及录制、加载和视频协调器。

## 组件与所有权

| 组件 | 职责与共享范围 |
|---|---|
| session/宿主层 | 每个实例拥有一个游戏进程、Runtime、IPC 和隔离资源；同一时刻只有一个活动分支 |
| 分支与 checkout 管理 | 保存分支起点及有效材料引用，编排恢复/重算、目标确认和代次切换 |
| checkpoint 管理 | 管理所属 session、支持范围、生命周期、预算和释放；原生 payload 与恢复闭包归 AvZ |
| 脚本任务 | 管理检查/构建/运行身份、控制权、取消状态及结果 |
| trajectory-recorder 集成 | 收集实际事件、封存记录、关联执行句柄与证据引用；schema 归 recorder |
| trajectory-loader 集成 | 解析持久化材料、校验与生成重放计划，通过内部执行接口建立起点 |
| video-recorder 集成 | 可选画面/音频录制与时间轴任务，不承担状态恢复 |

共享后端不等于全局单例。独立后端实例各自拥有独立资源；指向同一 session 的客户端必须访问同一拥有者。多 session 可并行，单 session 内 checkout 串行。跨 session checkpoint 迁移只在 Runtime 明确支持时可用。

## 分支机制与搜索策略

后端管理执行分支的身份、父边界、当前活动位置、恢复材料与状态，不拥有候选排名、搜索树价值或求解器记忆。后者由 search/synthesis 或 LLM 控制器持有。

在线已有有效 live checkpoint 时直接恢复，不要求先封存轨迹。使用保留的 root/有序历史重算时由后端编排；读取持久化轨迹时调用 loader 解析和规划。loader 使用后端内部 session 执行接口，不能回调公共 checkout 导致递归加载。

请求显式给出 `fork_strategy` 和 `fallback_policy`。后端返回实际策略、重放工作量、到达边界与新执行代次。只在允许时回退，不将 FrameRef 当 checkpoint，也不将 live handle 序列化冒充持久化材料。快速恢复相对于历史长度近似 O(1)，不承诺任意 traj 首次加载的端到端 O(1)。

## 多客户端与动作控制权

每个 session 有串行变更通道，变更在游戏线程验证预期边界和执行代次。CLI 与 SDK 不能各持独立写入状态，以请求到达顺序代替调用者意图。基础 commit 仍为单动作，具体见[执行契约](05_session与执行契约.md#单动作提交契约)。checkout、脚本生命周期变更与 advance 同样要验证所属 session、控制权及当前代次。

原生脚本运行和外部动作采用显式控制模式：原生脚本控制、外部逐步控制，或允许记录的外部干预。第一版可先支持前两种互斥模式；干预模式须另行定义暂停边界、调度顺序和回执。不能默认为脚本与外部客户端可同时无序写入。

控制权转移需确认 Runtime 已到稳定边界并明确处理待执行脚本任务；恢复、换脚本或重建 root 产生新的执行代次。旧代次的写请求和执行令牌失效，仍有效的 checkpoint 按自己的生命周期保留。脚本装载版本不兼容时需拒绝旧 checkpoint。

## 记录、加载与数据集

Runtime 产生状态/动作/native 事实，后端补充实际分支、任务与执行关联，再交给 recorder。上层也可发出自身实验事件，但完整轨迹不得仅依赖模型 runner 主动记录；人工和直接 CLI/SDK 路径也必须能够录制。封存失败应显式报告，不将无证据执行伪装成成功封存。

loader 消费完整轨迹及可选 artifact，承担持久化解析、校验、重放计划与目标核对。dataset 拥有目录、manifest、索引、筛选、切分和样本转换；后端只接收解析好的显式执行材料引用。工具可组合导出入口，但不重新定义记录或数据集 schema。

训练样本须能区分执行分支与探索支路，并通过实验 metadata 引用观察/回退权限、预算、策略及上下文配置。通用 ArtifactRef/扩展 receipt 可关联上层信息，LLM 私有上下文和搜索内部结构不硬编码进 recorder 核心格式。

## 生命周期与失败

客户端退出不释放后端拥有的长期 session；显式 close 或声明的租期/清理策略才释放资源。Session 实例只管理自身，后端的会话注册表/worker 池是另一个显式组件。

超时、断线或取消不证明请求未执行。后端按 request_id 保留可查询的执行状态，声明查询保留范围；窗口外无法确认时返回未知，阻止盲目重试。部分恢复或无法确认稳定边界时禁止继续变更，直到有效状态重新建立。事件漏收、任务失败与资源清理失败分别报告。

## 实现待定项

传输协议、宿主部署、SDK 语言、命令名称、任务保留窗口、控制权租期和托管 REPL 待实现设计确定。本设计确定资源归属和语义边界，不将目录划分等同于独立建仓，也不声明任意 C++ 脚本已支持完整恢复。
