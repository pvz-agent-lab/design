# 任务、记录与资源生命周期

控制后端将长任务、执行请求、资源与持久化证据关联，允许短生命周期 CLI 和持续连接的 SDK 使用同一会话。

## 内部服务

| 服务 | 拥有的状态 | 主要操作 | 失败时的责任 |
|---|---|---|---|
| SessionRegistry / WorkerPool | session 身份、宿主连接、隔离目录与分配状态 | create、attach、status、close、allocate | 区分客户端断线和游戏退出，报告清理失败 |
| ControlArbiter | 控制模式、写入拥有者、排队请求、当前代次 | acquire、transfer、submit、pause | 拒绝无权和旧代次写入，不靠到达顺序推断意图 |
| BranchRegistry | 分支身份、父边界、已确认 tip 与 active checkout 关联 | create、resolve、list、绑定活动位置 | 不提前更新 tip，不覆盖既有轨迹 |
| CheckoutPlanner / Executor | 目标、材料、计划与执行进度 | plan、restore、recompute、verify | 报告实际路径、部分执行和不可变更状态 |
| CheckpointManager | live handle、所属 session、兼容性、使用引用和内存预算 | capture、pin、release、evict | 不驱逐执行任务正在使用的材料，不声称旧 handle 可恢复 |
| ScriptService | 源码/构建身份、工具链诊断、装载版本和执行任务 | check、build、load、run、stop | 区分编译、装载与游戏执行结果，处理版本失效 |
| TaskRegistry / RequestJournal | 请求身份、进度、结果与保留期限 | query、wait、cancel、reconnect | 保留未知状态，避免把传输失败当未执行 |
| RecordingCoordinator | 录制配置、事件流位置、封存任务与证据关联 | start、append、seal、status | 显式记录漏收、写入失败或未封存 |
| LoaderAdapter | 持久化定位、版本校验和重放计划 | resolve、validate、load、verify | 拒绝材料不兼容，核对实际到达状态 |
| VideoCoordinator | 可选录制任务、输出与时间轴 | start、stop、status | 区分视频失败与游戏执行失败，标注 checkout |

这些是内部职责名称，不要求逐个建仓、独立进程或立即实现对应类。recorder/loader/video 的领域实现仍在各自组件；后端协调器拥有的是任务与资源关联。

## 请求与长任务

单动作请求返回实际执行回执；构建、长推进、checkout、轨迹封存和视频录制可以返回可查询任务。任务状态至少区分排队、执行中、成功、失败、取消请求中、已取消和结果未知；取消请求被接受不等于底层已经停止。

任务查询保留实际完成量、前后代次/边界、子操作结果、错误以及 FrameRef/ArtifactRef。幂等查询可以重试，变更是否可重试由 RequestId 的确认结果和保留窗口决定；不能换一个新 ID 重复结果未知的动作。

## 执行事实与记录事实

Runtime 产生观察、动作与 native receipts；后端补充实际 session/分支/任务关联后交给 recorder。recorder 定义公共 S、Frame、Transition、Episode、BranchRecord 及 seal；后端不维护另一份可编辑轨迹作为权威。

成功执行、成功写入、成功封存是不同状态，结果分别返回。配置为完整录制时，后端负责保证约定事件顺序并检测缺口；无法保证时显式返回不完整状态，不能以最终 observation 补写冒充完整历史。未录制 live 任务可用于临时探索，但不自动拥有冷启动复现材料。

dataset 消费封存记录并拥有 manifest、筛选、切分和转换。搜索过程中的失败支路、成功路径与策略可用上下文通过实验 metadata 关联，后端不替上层决定哪些数据用于训练。

## 资源回收

| 资源 | 释放条件 | 对其他对象的影响 |
|---|---|---|
| 客户端连接 | 客户端退出或断线 | 不自动关闭长期 session；控制权按声明的断线策略处置 |
| Session / Runtime | 显式关闭或后端清理策略 | 所属 live 句柄失效，任务报告实际停止/失败状态 |
| Live checkpoint | 显式 release，或无 pin/在用引用且满足驱逐策略 | 分支证据仍在；后续 checkout 需其他材料或明确失败 |
| 逻辑分支引用 | 显式删除且满足引用约束 | 不删除不可变历史，不自动释放其他任务在用材料 |
| 请求/任务查询记录 | 超过声明保留期 | 后续查询返回过期/未知，不能据此断言从未执行 |
| 持久化轨迹/artifact | 独立、显式的存储保留策略 | 清理需保护被保留证据引用的材料，不能随 live 缓存驱逐一起删除 |
| REPL / 视频任务 | 各自执行宿主的关闭/停止规则 | 不自动跟随游戏 checkout；状态与输出单独管理 |

资源引用计数、pin 和租期是可选实现手段；必须实现的是可观察的生命周期、在用资源保护以及失败后的真实状态报告。持久化清理是独立能力，不因提供 branch delete 就默认启用破坏性历史清理。
