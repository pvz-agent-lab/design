# AvZ 在线 SDK 与 REPL

在线 SDK 为搜索、模型 runner、实验与采样程序提供可编程入口，与 CLI 共用后端控制契约。SDK 可以维持连接，返回类型化对象、任务和事件；搜索热路径不要求每个动作启动一次 CLI 进程。

## 公开对象与操作

SDK 提供 session、边界、分支、checkpoint、脚本任务及录制任务的引用，覆盖观察、单动作提交、推进、恢复、加载和资源释放。身份、生命周期与错误以[共享后端](04_共享控制后端.md)和[执行契约](05_session与执行契约.md)为准。

SDK 不在客户端复制一份权威活动分支状态，不绕过服务端边界验证。可本地缓存观察，但变更需使用实际返回的 BoundaryRef；恢复后的旧代次令牌不可继续提交。断线重连需重新查询会话、任务和代次；事件订阅须能发现缺口，不能把客户端漏收等同于游戏没有执行。

## REPL 的位置

第一版可使用外部 Python REPL 导入 SDK，保存变量、函数、候选代码与探索记录。解释器属于调用者执行环境，不默认进入 AvZ Runtime 或共享控制核心。若将来提供托管 REPL，需单独声明 REPL 的身份、所属调用者、重连、取消与清理生命周期。

游戏 checkout 不自动回滚整个 REPL。区分三类状态：

| 状态 | 所属与恢复规则 |
|---|---|
| 游戏与 AvZ 执行状态 | Runtime 按声明的恢复闭包恢复 |
| 候选程序执行状态 | 由 runner/脚本宿主按契约快照、重建或明确不支持 |
| 求解器探索记忆 | 搜索器/LLM 持有，允许保留失败经验 |

若 Python 策略使用计数器或待执行队列影响后续动作，只恢复游戏不能声称恢复了整个候选执行。runner 必须恢复该状态或从明确起点重建；纯观察驱动策略可以声明无此状态。REPL 中临时函数不自动成为可独立复现的最终程序产物。

## 调用者与预算

LLM 可以通过 CLI 或 SDK 在线决策、控制悔棋，也可以作为综合器生成候选代码。任务明确允许的观察、干预、回退与资源预算；不因使用 LLM 就改变底层执行契约。搜索器拥有候选选择与停止策略，后端执行其请求并报告实际资源消耗。

训练好的 policy 可以由可选 runner 通过 SDK 执行；train 的在线采样也可调用 SDK。模型、优化器、训练 batch 和搜索树均不进入公共控制协议或 recorder 核心 schema。
